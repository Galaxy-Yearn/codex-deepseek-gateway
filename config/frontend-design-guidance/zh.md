# 前端设计指导

在构建包含前端体验的应用时遵循以下说明：

## 以同理心构建

- 如果正在处理现有设计或上下文中提供了设计框架，你应仔细遵循现有约定，并确保新增内容与所用框架和现有应用设计一致。
- 在决定功能开发与设计布局、组件、视觉风格、屏幕文字、交互模式时，要深入思考目标受众。应用体验应显得完整、成熟且有质感。
- 你确保前端设计是针对应用的领域和主题量身定制的。SaaS、CRM 和其他运营类工具应让人感觉低调、实用且以工作为中心，而非插画式或编辑式风格：避免过大的首屏主视觉区、装饰性卡片堆砌布局和营销式构图；而应优先考虑密集但有组织的信息、克制的视觉风格、可预测的导航，以及为速览、比较和重复操作而构建的界面。游戏可以更具插画性、表现力、动画感和趣味性。
- 你确保应用内的常见工作流顺手、高效，又全面——用户在应用中能够流畅地在不同视图和页面之间浏览切换。

## 设计说明

- 需确保：工具用按钮中的图标，颜色用色块，模式用分段控件，二进制设置用切换/复选框，数值用滑块/步进器/输入框，选项集用菜单，视图用标签页；仅在指令明确时使用文本或图标+文本按钮。卡片保持 8px 或更小的边框半径，除非现有设计系统另有要求。
- 如果可以使用熟悉的符号或图标，不使用内部有文本的圆角矩形 UI 元素（例如，撤销/重做的箭头图标，粗体/斜体的 B/I 图标，保存/下载/缩放图标）。对于不熟悉的图标，设计悬停工具提示用于命名或描述该图标。
- 当存在对应图标时，你在按钮内使用 lucide 图标，而不是手工绘制的 SVG 图标。如果现有应用中启用了某个图标库，你使用该库中的图标。
- 构建目标用户认为自然的功能完备的应用控件、状态与视图。
- 你不使用可见的应用内文本描述应用的功能、键盘快捷键、样式、视觉元素或如何使用应用。
- 除非绝对必要，不应制作落地页；当被要求构建网站、应用、游戏或工具时，首屏应呈现真实直观的体验，而不是营销或说明性内容。
- 制作首屏主视觉页时，使用相关图片、生成的位图图片或铺满画面的沉浸式互动场景作为背景，并将文字直接叠放其上，而不是放进卡片；切勿使用卡片与文字分居两侧的图文分栏布局；切勿将主视觉文案或主要体验放在卡片内；切勿制作渐变或 SVG 首屏；如果真实图片或生成图片足以呈现主题，不要制作 SVG 主视觉插图。
- 在品牌、产品、场馆、作品集或特定对象的页面中，品牌/产品/场所/对象本身必须成为明显的视觉信号，而不应仅以小的导航文字或眉题（导语）的形式出现。首屏主视觉内容必须在所有移动端和桌面端视口（含宽屏桌面）中，均能露出下一节的局部内容。
- 在着陆页首屏区域中，应将 H1 标题设为品牌名、产品名、地名、人名，或明确具体的报价/品类；把描述性内容放在辅助文案中，而不是标题里。
- 网站和游戏必须使用视觉资源。你可以使用图像搜索、已知相关图像或生成的位图图像，而非 SVG（除非制作游戏）。主图及多媒体素材要真实呈现实际的产品、场所、物体、状态、游戏画面或人物；当用户需要检查实物时，避免使用暗色、模糊、裁剪、图库风或纯氛围的图像。对特殊定制的游戏资源，你使用自定义 SVG/Three.js 等。
- 对于具有既定规则、物理、解析或 AI 引擎的游戏或交互工具，你使用经过验证的现有库来实现核心逻辑，而不是自己从头实现，除非用户明确要求从头实现。
- 采用 Three.js 构建 3D 元素，主 3D 场景需采用满版（无白边）或无边框布局，且不得置于装饰卡片或预览容器内。在完成前，你通过 Playwright 截图和 canvas 像素级检查，验证它在桌面/移动视口上不是空白、构图正确、可交互/有动效，且引用的资源均按预期渲染且不重叠。
- 你不将 UI 卡片放在其他卡片内。页面区块不要采用悬浮卡片样式。仅将卡片用于单个重复项、模态框，以及确实需要框架包裹的工具/组件。页面区块须采用全宽通栏或无边框布局，且内部内容需限制宽度。
- 不添加独立球体、渐变球体或散景光斑作为装饰或背景。
- 确保文本在移动端和桌面端的所有视口中，均能完整容纳于其父级UI元素内。必要时换行；如果换行后仍放不进 UI 元素，使用动态尺寸使最长单词也能容纳。文本也不能遮挡文段前后的内容。同时也要给出专业且经过打磨的 UI 按钮和卡片内文本。
- 显示文本的字号和密度匹配其容器：只在真正的首屏主视觉中使用超大字号；在紧凑面板、卡片、侧边栏、仪表盘和工具界面中使用更小更紧凑的标题。
- 对于固定版式的 UI 元素（如面板、网格、工具栏、图标按钮、计数器或磁贴），应在设定稳定尺寸的基础上配置响应式约束，从而保证悬停态、标签、图标、组件、加载文本或动态内容不会因尺寸变化而引发整体布局偏移。
- 不要按视口宽度缩放字号。字母间距必须为 0，不能为负。
- 你不做单调配色：避免由单一色系主导的 UI，减少紫色/紫蓝渐变、米色/奶油色/沙色、深蓝/石板色和棕色/橙色/浓缩咖啡色系主导的风格；定稿前检查 CSS 颜色，如果页面视觉上接近这些主题之一就做调整。
- 你确保 UI 元素和屏幕上的文本不会出现混乱/重叠。这点极为重要，因为混乱/重叠会造成糟糕的用户体验。
